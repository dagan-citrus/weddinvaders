## PART A — Detailed design (implementer)

### Acceptance criteria
- **R1** (D8) `npm test` runs Vitest once (jsdom + Testing Library) over `src/**/*.test.{js,jsx}` only; exits 0.
- **R2** (D8) `npm run e2e` runs Playwright specs in `e2e/` against the production build; exits 0.
- **R3** (T1) A smoke test proves the app mounts, at component level and in a real browser.
- **R4** (G11) `npm run lint` exits 0 with 0 errors and 0 warnings, no rule disabled, gameplay unchanged.
- **R5** (G11) CI runs lint, unit tests, build and e2e on every pull request, any base.
- **R6** `src/useGameState.js.bak` is deleted.
- **R7** Knowledge docs describe the new tooling.
- **R8** `npm run build` still passes; `deploy.yml` untouched.

- **Test-builder only:** `src/App.test.jsx`, `e2e/smoke.spec.js`.

- **Test-builder may assume:** scripts `test` and `e2e`; Vitest `globals: false` (import `describe/it/expect` from `vitest`); jest-dom matchers and RTL cleanup registered by the setup file; canvas 2D context stubbed in jsdom; Playwright `baseURL` `http://127.0.0.1:4173`, chromium only.

### Risks and defaults
- **Playwright version drift between container and CI.** Default: exact pin; CI installs its own browser.
- **`localhost` resolving to IPv6.** Default: use `127.0.0.1` everywhere.
- **Port 4173 busy locally.** Default: `--strictPort` fails loudly; a running server is reused outside CI.
- **e2e rebuilds after `check` already built.** Default: accept (seconds) for a self-contained `npm run e2e`.
- **Canvas stub hides renderer bugs in jsdom.** Default: accept; e2e covers real painting.
- **jsdom never fires `Image.onload`.** Default: fine; component tests must not depend on assets being loaded.

## PART B — Test plan (test-builder)

Levels: component smoke (fast mount check, R1/R3) and e2e smoke (real canvas and loop, R2/R3). No unit tests in T1 because no pure logic is added; they start in T2.

Commands: `npm test`, `npm run e2e`, `npm run lint` (test files must lint clean).

### `src/App.test.jsx`
Uses Vitest + RTL; imports `CANVAS_WIDTH`, `GAME_HEIGHT`, `AMMO_ORDER` from `./constants`.
- **C1 (R1, R3)** given `render(<App />)`; expect `container.querySelector('canvas.game-canvas')` in the document with `width` attribute `String(CANVAS_WIDTH)` ("910") and `height` attribute `String(GAME_HEIGHT)` ("600").
- **C2 (R3)** given a render; expect `getAllByRole('button')` length `2 * AMMO_ORDER.length + 2`, and buttons named `👰 SHOOT` and `🤵 SHOOT` each present exactly once.
- **C3 (R3)** given a render; expect text matching `/Bride — A\/D move/` and `/Groom — ←\/→ move/` in the document.
- **C4 (R4)** given a render; when `fireEvent.keyDown(window, { code: 'Space' })`, then `KeyS`, `ArrowUp`, `KeyW`, then `fireEvent.click(canvas)`; expect no throw and the canvas still in the document.
- **C5 (R4)** given a render; when `unmount()`; expect no throw and `document.querySelector('canvas')` to be null.

### `e2e/smoke.spec.js`
Uses `@playwright/test` and relative `page.goto('/')`.
- **E1 (R2, R3)** given `/`; expect `canvas.game-canvas` visible with attributes `width="910"` and `height="600"`.
- **E2 (R3)** given `/` and a `pageerror` listener registered before `goto`; when the canvas is visible and 500 ms pass; expect zero page errors.
- **E3 (R3, R4)** given `/`; expect, via `expect.poll`, that `getContext('2d').getImageData(10, 10, 1, 1).data[3]` equals `255`. This proves the loop and renderer painted the opaque background.
- **E4 (R4)** given `/`; when the canvas is clicked (title → playing), then `Space`, `KeyW`, `ArrowUp`, `KeyS` are pressed; expect zero page errors and the canvas still visible.

Do not assert the document title or root-path content beyond the above; T4 and T12 change them.
