# T5 — Site shell + landing page: design and test plan

Source: `docs/main-site-plan.md` (G1, G8–G11; D1, D3, D7; T5; consumers T6–T12), `docs/designs/T4.md` (A4, A5, K3, K4), `docs/designs/T2.md` A4.1, `docs/designs/T3.md` A4.7.
Grounded in the branch at `d8e58a8`. T3 and T4 are treated as designed interfaces. Nothing was executed.

Facts checked in the code:
- CSS is imported in two places only: `src/main.jsx` → `index.css`, `src/Game.jsx` → `Game.css`. `src/App.css` is imported nowhere. Vite emits one stylesheet, so every rule is global whatever is mounted.
- Rules that leak today: `Game.css` `*` and `body`; `index.css` `:root`, `a`, `a:hover`, `body`, `h1`, `button` (+ `:hover`, `:focus`) and the light-scheme block. `Game.jsx` renders only `div`, `canvas`, `button`, `span`, so `a`/`h1` rules never touch the game.
- `button:hover { border-color }` (0,1,1) currently beats `.ammo-btn` (0,1,0); `* { padding: 0 }` (0,0,0) loses to `button { padding }`. Any scoping must keep specificity identical.
- Game palette (`renderer.js`, `Game.css`): page `#050510`, panel `rgb(10,20,50)`, sky `#1a3a70`/`#22478a`, gold `#ffd700`, bride pink `#ff69b4`, groom blue `#4169e1`, green `#4caf50`. Fonts: bold `monospace` for headings and HUD, Arial for body.
- `SITE_CONFIG.contactEmail` is `contact@example.com` (`PLACEHOLDER_CONTACT_EMAIL`).

# PART A — DETAILED DESIGN (implementer)

## A1. Decisions

| # | Decision | Why |
|---|---|---|
| SD1 | **K3: surface attribute.** `App` sets `document.documentElement.dataset.surface` to `'game'` (routes `event`, `demo`) or `'site'` (everything else) in a `useLayoutEffect`. Every page-level rule in `Game.css` and `index.css` is prefixed with a zero-specificity `:where([data-surface='game'])`. Component rules (`.game-wrapper` … `.shoot-btn`) are untouched. | Same declarations, same order, same specificity, so the game's cascade is provably unchanged. Restructuring the game layout instead would risk the flex shrink-to-fit sizing of `#root`. |
| SD2 | **Site CSS is scoped by class and tokens.** Tokens are `--wv-*` custom properties on `:root` (inert for the game). All site rules sit under `.site` or `html[data-surface='site']`. | The game has no `.site` ancestor, so no site rule can reach it. |
| SD3 | **No hamburger.** The nine nav links wrap (`flex-wrap`) under the brand; the header is not sticky. | Nine short labels take three rows (about 130px) at 360px, shown once at the top. A hamburger needs state, `aria-expanded`, Escape and focus handling, and hides links from T4's tests, for no gain at this size. |
| SD4 | **Hero is a DOM/CSS mock** (`GameplayPreview`) built from `defaultEvent.items` emoji. No screenshot asset, no game mount. | No binary to recapture when the game changes, scales to any width, costs no game loop. It is labelled as an illustration. |
| SD5 | **Home `h1` stays `Weddin'Vaders`**; the pitch headline is a paragraph beneath it, mirroring the game's title screen. | Keeps every T4 A5 heading hook valid. |
| SD6 | **Content lives in `src/content/en/`**, re-exported by `src/content/index.js`. Plain frozen data, no JSX. | G9, D3: a later locale is a sibling folder plus one changed line. |
| SD7 | **K4:** `navigate` scrolls to top; `SiteLayout` moves focus to `<main>` when `routeId` changes after mount. | Scroll belongs to the navigation act; focus belongs to the layout that owns `<main>`. |

## A4. Component APIs

### A4.1 `src/App.jsx` (addition to T4 A4.4)
```jsx
const surface = route.id === ROUTE_ID.EVENT || route.id === ROUTE_ID.DEMO ? 'game' : 'site';
useLayoutEffect(() => { document.documentElement.dataset.surface = surface; }, [surface]);
```
No cleanup. Game routes still return `<EventPage>` / `<DemoPage>` with no layout.

### A4.2 `SiteLayout({ routeId, children })`
```
<div class="site">
  <a class="site-skip" href="#main">{common.skipToContent}</a>
  <header class="site-header"><div class="site-container site-header-inner">
    <Link class="site-brand" to="/">{SITE_CONFIG.name}</Link>
    <nav class="site-nav" aria-label={common.nav.ariaLabel}>   // 'Site'
      one <Link class="site-nav-link"> per NAV_ROUTES entry; text common.nav.labels[route.id];
      aria-current="page" when route.id === routeId, attribute absent otherwise
    </nav>
  </div></header>
  <main id="main" class="site-main" data-route={routeId} tabIndex={-1} ref={mainRef}>{children}</main>
  <footer class="site-footer"><div class="site-container">
    <p class="site-footer-tagline">{common.footer.tagline}</p>
    <nav class="site-footer-nav" aria-label={common.footer.navAriaLabel}>   // 'Footer'
      <Link> per FOOTER_ROUTE_IDS; text common.footer.linkLabels[id]; no aria-current
    </nav>
    <a class="site-footer-contact" href={`mailto:${SITE_CONFIG.contactEmail}`}>{common.footer.contactLabel}</a>
    <p class="site-footer-copyright">{fillTemplate(common.footer.copyright, { year, name })}</p>
  </div></footer>
</div>
```
- `FOOTER_ROUTE_IDS = [ROUTE_ID.PRIVACY, ROUTE_ID.TERMS, ROUTE_ID.ORDER]`; each `to` is the `path` of the matching `NAV_ROUTES` entry.
- `year = new Date().getFullYear()`, `name = SITE_CONFIG.name`.
- The brand link is outside `<nav>` and never carries `aria-current`.
- Focus: `const previous = useRef(routeId); useEffect(() => { if (previous.current !== routeId) { previous.current = routeId; mainRef.current.focus({ preventScroll: true }); } }, [routeId]);` Comparing with the previous id (not a first-render flag) is StrictMode-safe.

### A4.3 `HomePage()`
A fragment of four `<section class="site-section home-…" data-section="…">`, each with an inner `.site-container`:
1. `hero`: `<h1 class="home-title">{SITE_CONFIG.name}</h1>`, `<p class="home-headline">`, `<p class="home-subhead">`, `<div class="home-actions">` with `<Link class="site-btn site-btn-primary" to="/demo">` and `<Link class="site-btn site-btn-secondary" to="/order">`, `<ul class="home-facts">` (one `<li>` per fact), then `<GameplayPreview label={home.hero.previewLabel} />` and `<p class="home-preview-caption">`.
2. `pitch`: `<h2>`, then `<ul class="home-features">` with one `<li class="site-card" data-feature={id}>` per feature: `<h3>` + `<p>`.
3. `steps`: `<h2>`, then `<ol class="home-steps">` with one `<li class="site-card" data-step={id}>` per step: `<h3>` + `<p>`. Step 3's body goes through `fillTemplate(body, { host: new URL(SITE_CONFIG.baseUrl).host })`.
4. `cta`: `<h2>`, `<p>`, the same two buttons (labels from `home.cta`).

CTA paths come from `ROUTE_ID` (`'/' + ROUTE_ID.DEMO`, `'/' + ROUTE_ID.ORDER`), not from content.

## A7. Game CSS scoping (exact selector changes; declarations untouched)

`src/Game.css`: `*` → `:where([data-surface='game']) *`; `body` → `:where(html[data-surface='game']) body`. Nothing else.

`src/index.css`, in this order:
1. New first rule: `:root { color-scheme: dark; background-color: #050510; }` (paints before React mounts; the game's scoped rules below still override it in light scheme, as today).
2. `:root` → `:root:where([data-surface='game'])`.
3. `body` → `:where(html[data-surface='game']) body`.
4. `button`, `button:hover`, `button:focus, button:focus-visible` → each prefixed with `:where([data-surface='game']) `.
5. In the light-scheme block: `:root` and `button` prefixed the same way.
6. Delete `a`, `a:hover` (both places) and `h1`.

For T6: wrapping an embedded game in `<div data-surface="game">` re-applies the reset and button base inside site chrome; the `body` and `:root` rules deliberately do not follow.
