Source: `docs/main-site-plan.md` (T6; G6, G7, G9, G10), `docs/designs/T2.md` (A3–A5), `T3.md` (TD6/TD7), `T4.md` (RD5, A4), `T5.md` (SD1, A5–A8, Q8).
Grounded in `origin/claude/festive-keller-zq4u6j` (T1–T3 merged; the local checkout is 11 commits behind it). T4 and T5 are designed interfaces. Nothing was executed.

Facts checked in the code:
- `useGameState` listens on `window` for `keydown`/`keyup`. It calls `preventDefault()` on Space and the four arrows on every event, whatever the focus or phase. In the `title` phase **any** keydown starts the game, including Tab and Shift.
- Touch controls (`Game.jsx`) are three ammo buttons and one SHOOT button per player. There is **no sideways movement on touch**.
- `.game-wrapper` has `min-height: 100vh; padding: 16px`; `.game-container` has `max-width: 820px`. Two `.mobile-player` blocks are roughly 180px min-content each, wider than a 328px container, and nothing clips them once `body { overflow-x: hidden }` no longer applies.
- `src/gameSources.test.js` `test_default_images_only_in_default_event` allows the text `-nobg.png` only in `src/events/defaultEvent.js`.
- The renderer hardcodes `−30% OFF` on discount items, `🎀` in the HUD discount line, `⚡ DANGER`, `💣 TRAP!`, `⏳ SLOW TIME`, and "guests"/"family" in the title help. Panel level names are cut after 14 characters.
- `usePathname` snapshots only `pathname`, so a query-only change does not re-render `App`.

## A1. Decisions

| # | Decision | Why |
|---|---|---|
| DD1 | **`/demo` is a site page inside `SiteLayout`**, with the game embedded in `<div data-surface="game">`. Supersedes T4 RD5/R5 for `/demo`; event pages stay chrome-free. | The page needs a switcher, an explanation and a route to `/order`; on a chrome-free page all of that would be re-invented. The chrome-free view stays one click away (DD6). |
| DD2 | **Surface mapping:** `html[data-surface]` is `game` only for `ROUTE_ID.EVENT`; `/demo` is `site`. | T5 Q8. The `body`/`:root` game rules must not apply under site chrome. |
| DD3 | **Game modules are not touched.** Embedding problems are fixed by `.demo-*` CSS overrides and one key guard in `DemoPage`. | G7. |
| DD4 | **Switcher = two links** in `<nav aria-label="Sample games">`, the active one with `aria-current="true"`. | DD5 | **Switching uses `navigate(path, { replace: true, scroll: false })`**: no history entry, no jump to top. The page derives the sample from `location.search`, so the nav link `Demo` returns to classic. | One source of truth; needs a `useLocationSearch` hook and a `scroll` option (A4.2). |

| DD7 | **Images: the sample reuses the default artwork** via `images: defaultEvent.images`, and the page says so. No new files; `src/assets/events/` is not created. | Truthful and free of art risk. Referencing the object, not the PNG filenames, keeps the T3 source scan green. |
| DD8 | **Key guard on `/demo` only:** Tab and bare modifier keys never reach the game. | Otherwise tabbing to the skip link starts the clock. |

## A4. APIs

### A4.1 `src/pages/demoSamples.js` (no JSX; imports from `'../events'`)
```js
export const DEMO_EVENT_PARAM = 'event';
export const DEMO_SAMPLES     // frozen [{ id: 'classic', event: defaultEvent }, { id: 'garden', event: mayaAndNoahEvent }]
export function getDemoSample(search)       // → sample; the first one when the parameter is missing, empty or unknown; never throws
export function getDemoSamplePath(sample)   // → '/demo' for the first sample, '/demo?event=<id>' otherwise
```
`getDemoSample` reads `new URLSearchParams(search).get(DEMO_EVENT_PARAM)`, trims and lowercases it, and compares it with `id`. The `/demo` part comes from `ROUTE_ID.DEMO`.

### A4.2 `src/navigation.js`
```js
export function useLocationSearch()   // → window.location.search; same popstate subscription as usePathname
export function navigate(to, { replace = false, scroll = true } = {})
```
`window.scrollTo(0, 0)` runs only when `scroll && !to.includes('#')`. Defaults keep T4/T5 behaviour.

### A4.3 `DemoPage()` (rendered by `App` as `<Page route={route} />`; the prop is unused)
```
<section class="site-section demo-intro" data-section="intro">        .site-container
  <h1>{demo.heading}</h1> <p>{demo.intro}</p>
<section class="site-section demo-play" data-section="play">          .site-container
  <nav class="demo-switcher" aria-label={demo.switcher.ariaLabel}>
    per DEMO_SAMPLES: <Link class="demo-sample-link" data-sample={id} to={getDemoSamplePath(sample)}
                            aria-current={active ? 'true' : undefined} onClick={select}>{label}</Link>
  </nav>
  <div class="demo-stage" data-testid="demo-stage" data-surface="game"
       data-sample={sample.id} data-event-slug={sample.event.slug}>
    <Game event={sample.event} />
  </div>
  <p class="demo-sample-summary" data-testid="demo-sample-summary">{summary of the active sample}</p>
  <p class="demo-photo-note">{demo.photoNote}</p>
  <p><Link class="demo-own-page-link" to={getEventPath(sample.event.slug)}>{demo.ownPage.link}</Link> {demo.ownPage.hint}</p>
<section class="site-section" data-section="controls">                .site-container
  <h2>, then per demo.controls.groups: <div class="site-card" data-controls={id}> <h3> + <ul><li>…
  <p>{demo.controls.ammoNote}</p>
<section class="site-section" data-section="differences">             .site-container
  <h2>, <ul class="demo-differences"> per item: <li class="site-card" data-difference={id}> <h3> + <p>
<section class="site-section" data-section="cta">                     .site-container
  <h2>, <p>, <Link class="site-btn site-btn-primary" to="/order">, <Link class="site-btn site-btn-secondary" to="/customize">
```
- `sample = getDemoSample(useLocationSearch())`. Labels and summaries are looked up in `demo.switcher.samples` by `id`.
- `select(e)`: return (letting `Link` and the browser act) when `e.button !== 0` or a modifier is held. Otherwise `e.preventDefault()` and, if the sample is not already active, `navigate(getDemoSamplePath(sample), { replace: true, scroll: false })`. T4's `Link` skips its own `navigate` when the default is prevented.
- `<Game>` gets no `key`: `Game` already remounts on a new slug (TD6).
- CTA paths come from `ROUTE_ID`, not from content.
- Key guard (DD8): an effect adds a **capture-phase** `keydown` listener on `document` that calls `event.stopPropagation()` when `event.key` is `Tab`, `Shift`, `Control`, `Alt` or `Meta`, and removes it on unmount. The game's listener is on `window` (bubble phase), so it never sees those keys. `preventDefault` is not called, so focus still moves.

## A7. `src/pages/DemoPage.css` (every selector starts with `.demo-`)

- `.demo-intro`: bottom padding 16px, so the game sits high.
- `.demo-switcher`: flex, wrap, 8px gap, 16px bottom margin.
- `.demo-sample-link`: `min-height: 44px`, inline-flex centred, `padding: 0 16px`, `1px solid var(--wv-border)`, radius, no underline, white text. `[aria-current='true']`: gold border and gold text.
- `.demo-stage`: `max-width: 100%`, `line-height: normal`, `font-family: Arial, sans-serif`, `color: #fff`. This neutralises what `.site` would otherwise make the game inherit.
- `.demo-stage .game-wrapper { min-height: 0; padding: 0; }`
- `.demo-stage .game-canvas { max-height: calc(100vh - 24px); }` — width and height stay `auto`, so the ratio is kept.
- `.demo-stage .mobile-player { min-width: 0; }` and `.demo-stage .ammo-buttons { flex-wrap: wrap; justify-content: center; }`, so the controls wrap instead of overflowing on phones.
- `.demo-stage button { touch-action: manipulation; }`
- `.demo-differences`: one column; three columns from 720px.

No `overflow: hidden` on the stage: an overflow must fail R9, not be clipped.
