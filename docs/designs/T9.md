# T9 — Order / contact page: design and test plan

Source: `docs/main-site-plan.md` (T9; G8, G9, G10, G11; D1, D6), `docs/designs/T8.md` (PD4, A4.2, A5, Q6), `T2.md` (A4, Q2, Q5), `T5.md` (A5 rules, A6), `T7.md` (CD1), `T4.md` (RD4), `T6.md` (DD6).
T1–T3 are in the working tree; T4–T8 are designed interfaces. The mailto string in B3.1 and the `suggestSlug` examples were produced by running the A4 algorithms in Node; nothing else was executed.

Facts checked:
- `SITE_CONFIG.contactEmail === PLACEHOLDER_CONTACT_EMAIL` (`contact@example.com`) today, so the production build that e2e runs against has ordering closed.
- `eventRegistry.getSlugStatus` trims and returns invalid → reserved → taken → available. `buildEventUrl` throws on a malformed slug. `DemoWedding` is always taken; `MayaAndNoah` only once T6 is merged.
- `usePathname` tracks the pathname only; `navigate` pushes the URL before `App` re-renders, so `location.search` is correct when `OrderPage` mounts.
- `encodeURIComponent` leaves `' ( ) ! *` unencoded; RFC 6068 allows all of them in a query.
- `site.css` has no rule for `<button>` or form controls; this page adds its own.

# PART A — DETAILED DESIGN (implementer)

## A1. Decisions

| # | Decision | Why |
|---|---|---|
| OD1 | **`?package=` is read once at mount**: `useState(() => getInitialPackageId(window.location.search, tierIds))`. Unknown or missing id → nothing selected. | The router does not track the query (RD4); the user's own choice must win afterwards. |
| OD2 | **Pure logic in `src/pages/orderForm.js`** returns error *codes*; messages live in content. `getSlugStatus`, `today` and package ids are injected. | Unit-testable without the registry, the clock or copy. |
| OD3 | **Submit sets `window.location.href` through an injectable `openMailto` prop and always renders a result panel** with a real `<a href={mailtoUrl}>`, the address, the subject, the message and a copy button. | A `mailto:` does nothing without a mail client. The anchor's `href` is observable in jsdom and Playwright without navigating. |
| OD4 | **Closed state**: while `isOrderingOpen(contactEmail)` is false, the form stays usable (live address check included), a notice sits above the fields, the submit button is `disabled`, and no result panel, mailto link or address can appear. | An order to `example.com` is lost silently (T2 Q2). The notice comes first so nobody fills the form before learning this. It disappears with a one-line config change. |
| OD5 | **Two length safeguards.** `NOTES_MAX_LENGTH = 600`; and if the URL still exceeds `MAILTO_MAX_LENGTH = 2000`, the mailto body carries a marker instead of the notes while the panel shows the full message. | 600 ASCII characters give a URL of about 1,400. The same count in Hebrew encodes to about 3,600, so a character cap alone is not enough. |
| OD6 | **Suggestion order is groom then bride** (`DanAndShelly`); form order is bride then groom. | Matches T7's example address and the game's `Bride & Groom` order. |
| OD7 | **FAQ is always-open `h3` + `p`**, not `<details>`. | Eight short answers; nothing worth hiding; heading navigation and in-page search work without interaction. |
| OD8 | `h1` is `route.title` (`Order`). | Keeps T4, T5, T7 and T8 hooks. |
| OD9 | Package and add-on names come from `pricing`; no price is shown. | One source; D7 numbers stay on `/pricing`. |

## A4. APIs

### A4.1 `src/pages/orderForm.js` — constants, validation, suggestion

```js
export const NAME_MAX_LENGTH = 40;
export const NOTES_MAX_LENGTH = 600;
export const EMAIL_MAX_LENGTH = 254;
export const MAILTO_MAX_LENGTH = 2000;
export const UNSURE_PACKAGE_ID = 'unsure';
export const FIELD_ORDER = ['brideName','groomName','weddingDate','slug','package','email','notes'];
export const ORDER_ERROR = { REQUIRED:'required', INVALID:'invalid', PAST:'past',
  RESERVED:'reserved', TAKEN:'taken', TOO_LONG:'tooLong' };   // frozen
export const EMPTY_ORDER = { brideName:'', groomName:'', weddingDate:'', slug:'',
  package:'', addons:[], email:'', notes:'' };                // frozen

export function isOrderingOpen(contactEmail = SITE_CONFIG.contactEmail)       // → boolean
export function getInitialPackageId(search, packageIds)                       // → id | ''
export function toIsoDate(date = new Date())                                  // → 'YYYY-MM-DD', local time
export function suggestSlug(firstName, secondName)                            // → slug | ''
export function validateOrder(order, { today, getSlugStatus, packageIds })    // → { [field]: code }
```

- `isOrderingOpen`: true only for a string matching `EMAIL_PATTERN = /^[^\s@]+@[^\s@]+\.[^\s@]+$/` that is not `PLACEHOLDER_CONTACT_EMAIL`.
- `getInitialPackageId`: `new URLSearchParams(search).get(PACKAGE_QUERY_PARAM)`; returned only if `packageIds.includes(it)` (case-sensitive).
- `suggestSlug`: for each name, `s = String(name ?? '').normalize('NFD').replace(/[\u0300-\u036f]/g, '')`. If `/(?![A-Za-z])\p{L}/u.test(s)` the part is `''`. Otherwise split on `/[^A-Za-z0-9]+/`, drop empties, uppercase each word's first character, keep the rest, join. Either part empty → `''`; else `(first + 'And' + second).slice(0, SLUG_MAX_LENGTH)`.
- `validateOrder` trims strings and returns only failing fields:

| Field | Codes, in order |
|---|---|
| `brideName`, `groomName` | empty → `required`; longer than 40 → `tooLong` |
| `weddingDate` | empty → `required`; not `YYYY-MM-DD` or not a real date → `invalid`; `< today` (string compare) → `past` |
| `slug` | empty → `required`; otherwise `getSlugStatus(slug)`: `invalid` / `reserved` / `taken` |
| `package` | not in `[...packageIds, 'unsure']` → `required` |
| `email` | empty → `required`; fails `EMAIL_PATTERN` or over 254 → `invalid` |
| `notes` | over 600 → `tooLong` |

`addons` is never an error; unknown ids are dropped when composing.

### A4.2 `src/pages/orderForm.js` — message and mailto

```js
export function buildOrderMessage(order, ctx)            // → { subject, body }
// ctx = { template, siteName, eventUrl, packageName, addonNames, omitNotes = false }
export function buildMailtoUrl({ to, subject, body })    // → string
export function composeOrder(order, ctx, to)             // → { subject, body, mailtoUrl, notesOmitted }
```

`template` is `order.message` from content. `body` is these lines joined with `\n`, each filled by one `fillTemplate` call (user text is only ever a value, never a template):

```
{intro}                    New order from the {site} order form
(blank)
{bride}                    Bride: {value}
{groom}                    Groom: {value}
{date}                     Wedding date: {value}
{address}                  Requested address: {value}      ← eventUrl
{package}                  Package: {value}                ← packageName
{addons}                   Add-ons: {value}                ← addonNames.join(', ') or template.none
{email}                    Reply to: {value}
(blank)
{notesHeading}             Notes:
notes                      trimmed, \r\n → \n; empty → template.none; omitNotes → template.notesOmitted
```
Subject: `fillTemplate(template.subject, { site, groom, bride, slug })` → `{site} order: {groom} & {bride} ({slug})`.

`buildMailtoUrl`: `enc = (s) => encodeURIComponent(s.replace(/\r?\n/g, '\r\n'))`; result `` `mailto:${encodeURIComponent(to).replace(/%40/g, '@')}?subject=${enc(subject)}&body=${enc(body)}` ``. CRLF line breaks per RFC 6068; no `+` for spaces.

`composeOrder`: build the full message and URL. If `url.length > MAILTO_MAX_LENGTH` and notes are non-empty, rebuild the URL from `buildOrderMessage(…, { omitNotes: true })` and set `notesOmitted: true`. The returned `subject` and `body` are always the full ones.

Controls:

| Field | Control | Required | Attributes |
|---|---|---|---|
| `brideName`, `groomName` | `type="text"` | yes | `maxLength={40}`, `autoComplete="off"` |
| `weddingDate` | `type="date"` | yes | `min={toIsoDate()}` |
| `slug` | `type="text"` | yes | `maxLength={40}`, `autoCapitalize="none"`, `spellCheck={false}`, `autoComplete="off"` |
| `package` | radios | yes | — |
| `addons` | checkboxes | no | — |
| `email` | `type="email"` | yes | `autoComplete="email"`, `maxLength={254}` |
| `notes` | `textarea`, 5 rows | no | `maxLength={600}` |

Required inputs carry `required` (semantics only; the form is `noValidate`).

Behaviour:
- **Suggestion (R4).** While `!slugEdited`, a name change sets `slug = suggestSlug(groomName, brideName)`. Slug `onChange` sets `slugEdited = value !== ''`. The `fields.slug.noSuggestion` hint (`data-testid="order-slug-nosuggest"`) shows when both names are non-empty, the suggestion is `''` and `!slugEdited`.
- **Slug messages (R5).** The slug field has no `-error` paragraph. One `<p id="order-slug-status" role="status" data-testid="order-slug-status" data-status={…}>` is rendered when the trimmed value is non-empty (text `slugStatus[status]`, tokens `{min}`/`{max}` from the slug constants) or when it is empty and its error is shown (`data-status="required"`, text `errors.slug.required`). When the status is `available`, also `<p data-testid="order-slug-preview">` with `fillTemplate(fields.slug.preview, { url: buildEventUrl(trimmed) })`.
- **ARIA (R6).** `aria-describedby` lists the hint id and, while shown, the error id; for slug it is always `order-slug-hint order-slug-status`. `aria-invalid="true"` only while an error is shown, absent otherwise; for `package` it sits on the fieldset.
- **Submit.** If `!open`, return. Set `submitted`. On errors, focus `#order-${first}` (for `package`, the first radio) and stop. Otherwise `result = composeOrder(trimmedValues, ctx, contactEmail)` with `siteName: SITE_CONFIG.name`, `eventUrl: buildEventUrl(slug)`, `packageName` = tier name or `fields.package.unsure`, `addonNames` in `pricing.addons` order. Then `openMailto(result.mailtoUrl)` and focus the result heading in an effect. Re-submitting recomputes.
- **Copy.** `await navigator.clipboard.writeText(result.body)` → `copied`. If the API is missing or rejects, `textarea.select()` and show `copyFailed`.

CSS: `.order-form` is one column, `max-width: 640px`; `.order-input` is full width, `min-height: 44px`, `font: inherit` at 16px (stops iOS zoom), `--wv-surface` background, `1px solid var(--wv-border)`, white text; `[aria-invalid='true']` gets a `--wv-pink` border; `.order-error` is pink; `[data-status='available']` green, other statuses pink; radio and checkbox labels are 44px-high flex rows; `.order-submit` and `.order-copy` set `font: inherit; cursor: pointer; border` (`:disabled` → `opacity: .5; cursor: not-allowed`); `.order-notice` copies T8's notice (2px dashed gold); `.order-message` is full width, monospace, `--wv-surface-2`.
